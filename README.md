# ASIC ToolBox — Single-File Windows EXE

**Это отдельный вариант проекта ASIC ToolBox для сборки одного автономного Windows `.exe`.** Исходный проект распространяется в portable-папке; этот вариант использует Node.js SEA и встраивает сервер, Node runtime, интерфейс, npm-зависимости и `grpcurl.exe` внутрь исполняемого файла. Иконка EXE берётся из `public/app-icon.ico`. Для сборки на Windows выполните `npm ci` и `npm run build:windows`; результат появится в `dist/ASIC ToolBox.exe`. Из GitHub Actions скачайте артефакт `ASIC-ToolBox-Windows-SEA` со страницы успешного запуска во вкладке **Actions**; внутри ZIP будет тот же EXE. Подробности: [WINDOWS_EXE.md](WINDOWS_EXE.md).

Пользовательские данные этой версии сохраняются в `%LOCALAPPDATA%\ASIC ToolBox`, а не рядом с EXE. При первом запуске из старой portable-папки данные переносятся автоматически, если соответствующих файлов ещё нет в новом каталоге.

## Назначение приложения

Локальный веб-инструмент для ЦОД: добавление диапазонов IP, сканирование Braiins OS через REST API, gRPC и legacy BOSminer API, диагностика ошибок и расчёт миксов внутри выбранного ЦОД.

> **Читаемый код:** исходники JavaScript, HTML и CSS отформатированы Prettier. Запустить форматирование повторно можно командой `npm run format`; синтаксис и тесты проверяются командой `npm run check`.

## Запуск Windows `.exe` без прав администратора

Скопируйте только `ASIC ToolBox.exe` на Windows-ПК и запустите его. Отдельно устанавливать Node.js или хранить рядом папки приложения не нужно. Сервер доступен только локально на `127.0.0.1`; браузер открывается автоматически. Старый запуск из portable-папки через `run-windows.cmd` тоже сохранён. Подробности и расположение данных: [WINDOWS.md](WINDOWS.md) и [WINDOWS_EXE.md](WINDOWS_EXE.md).

Приложение слушает только `127.0.0.1`, а соединения к ASIC выполняются с этого ПК на HTTP 80 (REST), TCP 50051 (gRPC) и/или TCP 4028 (BOSminer API) в зависимости от выбранных переключателей. Поэтому ПК должен иметь сетевой доступ к VLAN/подсети ASIC. Пользовательские данные хранятся в `%LOCALAPPDATA%\ASIC ToolBox`.

## Запуск в Linux/macOS

```bash
cd /home/ubuntu/asic-mix
npm start
```

Откройте `http://localhost:4180`.

Переменные окружения:

- `PORT` — порт HTTP-сервера, по умолчанию `4180`.
- `HOST` — адрес bind, по умолчанию `127.0.0.1`.
- `ASIC_USER` — логин, по умолчанию `root`.
- `ASIC_PASSWORD` — пароль, по умолчанию `root`.

## Что определяется

Сканер поддерживает три API: Braiins REST (`http://ASIC_IP/api/v1`, порт 80), Braiins Public API gRPC (`50051`) и legacy BOSminer/CGMiner-compatible API (`4028`). REST выбран по умолчанию: нативный HTTP-клиент Node.js использует keep-alive и не запускает отдельный `grpcurl` для каждого RPC. gRPC и TCP 4028 остаются доступными через переключатели. Если включено несколько API, они идут в порядке REST → gRPC → TCP 4028 и переключение происходит только при ошибке предыдущего способа.

При сканировании REST выполняются вход, чтение сведений о майнере, платах и журнала ошибок параллельно; сбой чтения журнала не отменяет остальные данные и выводится как диагностическое предупреждение. Журналы ошибок показываются у устройств со статусами проверки, неисправной платы и offline. Для снижения риска ложного offline стандартная параллельность остаётся 12, но очередь динамическая: медленное устройство не блокирует запуск следующего. В результатах сохраняется общее время сканирования и длительность проверки каждого ASIC.

Для изменения параллельности задайте `SCAN_CONCURRENCY` перед запуском (допустимо 1–24, по умолчанию 12). Для Braiins OS Public API gRPC portable `grpcurl` по-прежнему включён в Windows-комплект.

## Правила микса

- За один скан выбирается ровно один ЦОД.
- Миксы строятся только внутри выбранного ЦОД.
- В миксы попадают только ASIC с `1/3` или `2/3` рабочих плат.
- Группировка идёт по **модели платы** (`boardModel`), а не по терахешам.
- ASIC с `0/3` рабочих плат помечаются «Проверить».
- ASIC с `3/3` рабочих плат скрыты из таблицы по умолчанию, но доступны через переключатель.
- Офлайн-устройства скрыты из таблицы по умолчанию и доступны через отдельный переключатель «Показывать офлайн».

## Формат результатов сканирования

Каждый ASIC выводится одной строкой: IP является ссылкой на веб-интерфейс устройства, далее показываются модель ASIC, объединённый список моделей плат, отдельные строки для 1-й/2-й/3-й платы с текущим хешрейтом в TH/s с двумя знаками после запятой, список неисправных плат, итог `x/3` и статус. Плата с нулевым текущим хешрейтом считается неисправной.

## Расчёт миксов и печать

Группы микса строятся только внутри выбранного ЦОДа и отдельно по модели платы. Внутри группы:

- **реципиенты** получают недостающие платы до `3/3`; сначала закрываются ASIC `2/3`, затем ASIC `1/3`;
- **доноры** полностью разбираются: все их рабочие платы передаются, после операции донор становится `0/3`;
- количество операций определяется балансом рабочих плат, а не количеством пар ASIC;
- один донор `2/3` отдаёт 2 платы, донор `1/3` — 1 плату;
- лишние доноры или реципиенты отображаются отдельно как «Не используются в текущем миксе» и не попадают в печать результата.

Каждую группу можно развернуть. Группа занимает всю ширину окна и содержит две явно видимые колонки: доноры и реципиенты. IP в списках кликабелен. Кнопка **«Печать всей группы»** печатает всех доноров и всех реципиентов этой модели платы одним заданием; на каждой этикетке роль определяется автоматически. Печать открывается стандартным окном Windows, где выбирается установленный принтер этикеток TT-200. На этикетке печатаются последние две части IP (например, `38.51`), роль справа, уникальный список моделей плат под IP и неисправные платы крупно (`HB 1,3`).

## Безопасность

Приложение рассчитано на закрытую локальную сеть. Пароль используется только сервером во время запроса и не отдается браузеру. Не публикуйте этот сервер в интернет без отдельной аутентификации и TLS.

## Резервная копия и состояние приложения

- Проверка локального сервера: `http://127.0.0.1:4180/api/health`.
- Скачать резервную копию данных: `http://127.0.0.1:4180/api/backup/export`.
- Экспорт содержит настройки ЦОДов, карты, legacy `state.js` и сохранённые JSON-планы из `saves/`. Он не включает исполняемые файлы и секреты окружения.
- Перед ручным восстановлением остановите приложение и скопируйте текущий каталог. Экспорт пока не имеет функции автоматического импорта.
- `state.json` и `maps.json` записываются через временный файл; перед перезаписью сохраняется `.bak`.
