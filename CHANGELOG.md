# Журнал изменений

## 1.4.6 — 2026-10-30

### Добавлено

- Отдельная страница «Конфликты IP» (`/ip-conflicts.html`) с повторным опросом выбранного ЦОДа по 2–6 раундам и выбором существующего протокола ASIC.
- API `POST /api/ip-conflicts`, прогресс через существующий endpoint и отмена штатным `/api/scan/cancel`; учитываются IP карты ЦОДа, а при пустой карте — диапазон/CIDR.
- Сравнение доступных серийных номеров, MAC из локальной таблицы соседей и аппаратных отпечатков; результаты разделяют подтверждённые сигналы и поводы для ручной проверки.
- Unit-тесты анализа конфликтов IP и инструкция `docs/IP_CONFLICTS.md`.

### Ограничения

- Серийный номер зависит от полей, возвращаемых конкретной версией/прошивкой API.
- ARP/neigh MAC может быть MAC шлюза при маршрутизации или кешированным значением; он не считается универсально достоверным.
- Проверка не изменяет устройства/сетевое оборудование и не доказывает отсутствие конфликта при пустом результате.

## 1.4.5 — 2026-10-27

### Исправлено

- Цвета карт теперь определяются прошивкой: Braiins OS — зелёный для 3/3, оранжевый для 1/3–2/3, красный для 0/3; SLEEP имеет отдельный синий цвет. Любая другая или не подтверждённая прошивка показывается фиолетовым независимо от ratio.
- Hybrid и прямой CGMiner-скан сначала быстро опрашивают весь список, затем ограниченным пулом до 8 устройств выполняют REST-уточнение только для online `0/3` или `check` результатов Braiins/неопределённой прошивки, исключая SLEEP и явно распознанные сторонние прошивки. Успешный Braiins REST заменяет неполный CGMiner-результат, определяет SLEEP и передаёт данные по платам в таблицу/карту; при неподдерживаемом REST сохраняется CGMiner-ответ.
- Под картой в список управления попадают только подтверждённые Braiins OS устройства `0/3`, не SLEEP; их карточки получают детальные платы для существующих Save and Apply / Resume действий.
- Общая таблица показывает Braiins `0/3` красным, SLEEP отдельно, а другие прошивки и их платы — фиолетовым. Счётчик проблемных устройств не включает сторонние прошивки и SLEEP.

### Проверки

- Добавлены регрессионные тесты выбора адресов для REST-уточнения: подтверждены `0/3` и `check`, исключены SLEEP, offline и частичные `1/3`.
- Полные проверки проекта выполняются перед упаковкой; реальные ASIC в среде разработки не опрашиваются.

## Дополнение — 2026-10-27 (Auto, состояния плат и размер пачки)

- В Auto проблемный Braiins-ответ REST/gRPC без распознанного состояния дополнительно сверяется через CGMiner; явные Paused/Sleep сигналы ищутся не только в SUMMARY/STATS, но и в статусах DEVS/DEVDETAILS. Это позволяет классифицировать SLEEP на старых версиях, если прошивка публикует признак паузы в legacy API.
- CGMiner-карты с достоверными данными по трём цепочкам показывают 0/3–3/3 и зелёный/жёлтый/красный статус; сторонняя прошивка сохраняет фиолетовый маркер. Агрегированный хешрейт не выдаётся за статус одной платы.
- Максимальный размер пачки увеличен с 64 до 256, включая проверку API, нормализацию сохранённой настройки и поле интерфейса.
- Проверено unit-тестами и статическими проверками; реальные майнеры не опрашивались в среде разработки.

## Дополнение — 2026-10-27

- CGMiner-ответ без надёжной сигнатуры прошивки больше не считается автоматически сторонней прошивкой и не окрашивается фиолетовым. Фиолетовый цвет используется только при явном маркере поддерживаемой сторонней прошивки; неизвестное устройство окрашивается по статусу плат.
- Явная пауза в CGMiner SUMMARY/STATS теперь отображается как SLEEP независимо от распознанной марки прошивки. Проблемные устройства с неизвестной прошивкой выборочно проверяются через Braiins REST, чтобы отличать спящие ASIC от реальных неисправностей; если REST не поддерживается, остаётся актуальный CGMiner-результат.
- Один общий хешрейт без данных по цепочкам больше не считается одной исправной платой: ratio остаётся неопределённым, и неизвестный ASIC попадает в выборочную диагностику вместо ложного 1/1.
- Тесты и статические проверки пройдены. Реальные ответы ASIC в текущей среде недоступны, поэтому редкие варианты CGMiner-полей требуют проверки на реальном устройстве.

## Изменения после 1.4.3 — 2026-10-26

### Быстрое сканирование и диагностика

- Режим по умолчанию изменён на гибридный: массовый проход всех ASIC выполняется только через CGMiner TCP API (VERSION, SUMMARY, DEVS, DEVDETAILS, STATS), без последовательного REST/gRPC fallback.
- Подробный опрос Braiins REST и NoPIC SSH выполняется только для ответивших проблемных устройств; мониторинг обновляет этот список раз в 5 секунд и убирает восстановившиеся ASIC.
- На странице карт в список проблемных для Braiins попадают также частично неисправные ASIC (1/3 и 2/3), а не только устройства 0/3.
- Если CGMiner сообщает о нескольких платах, статус частичного отказа теперь нормализуется как `degraded`, а не `healthy`.
- Старый автоматически выбранный `auto` мигрирует в `hybrid` один раз; явно сохранённый позднее выбор пользователя сохраняется без повторной миграции.

### Проверки и ограничения

- Добавлены регрессионные тесты CGMiner-only маршрута и определения частично отказавших плат.
- Статическая проверка и unit-тесты пройдены; сканирование реальных ASIC не запускалось в среде разработки.
- Стандартный CGMiner API даёт данные только в пределах полей, которые публикует конкретная прошивка. Управление платами остаётся Braiins-only через существующий gRPC API.

## 1.4.0 — 2026-10-26

### Добавлено

- Автоопределение Braiins OS через REST/gRPC с короткой предварительной проверкой TCP 4028; устройства на CGMiner-совместимой/стоковой прошивке читаются через отчётные команды `summary`, `devs`, `devdetails`, `stats` и `version`.
- Нормализация `GHS`, `MHS`, `KHS`, `THS` и `H/s` в общий хешрейт GH/s. Для сторонних прошивок на карте показывается TH/s и используется отдельный фиолетовый цвет.
- На ячейках карты добавлена видимая вторая строка с хешрейтом сторонней прошивки или состоянием `SLEEP`; время отклика остаётся в подсказке устройства. Легенда и цвета согласованы с темами.
- Braiins REST/gRPC результаты содержат семейство прошивки и состояние. Явные `paused`/`sleep`/`suspended` или остановка по команде оператора отображаются синим `SLEEP`; остановка из-за проблем пула не называется сном.
- Для сторонних прошивок не выполняется SSH-чтение NoPIC и не предлагаются Braiins-only действия управления платами. Они не попадают в мониторинг красных Braiins-устройств.
- Добавлены unit-тесты нормализации CGMiner и определения состояния Braiins.

### Ограничения и безопасность

- Для обнаружения стокового/стороннего устройства на нём должен быть включён и разрешён сетевой CGMiner API (обычно TCP 4028) для компьютера, где запущен ToolBox. Путь TCP 4028 использует только команды чтения.
- Хешрейт и статус цепочек зависят от того, какие поля конкретная прошивка публикует в `summary`/`devs`; при отсутствии данных приложение показывает нулевой/неопределённый результат, а не выдумывает число плат.
- Состояние `SLEEP` определяется только по явному сообщению о паузе/сне; без такого поля оно остаётся неопределённым.

### Проверки

- `npm run check` включает проверки синтаксиса и fixture-тесты совместимости.
- Живое подключение к реальным майнерам не выполнялось в этой среде.

## 1.1.4 — 2026-10-24

- Блок отображается только в тех ЦОДах, где после сканирования обнаружены ответившие устройства со статусом `check` или `ratio: 0/3` (офлайн-устройства исключены).

  3. **Окно логов Braiins OS (errors)**: выделенное консольное окно с журналом ошибок майнера (`/api/v1/miner/errors`), которое прокручивается отдельно от основной страницы (`overflow-y: auto`, `overscroll-behavior: contain`).

- Добавлена кнопка «Демо-данные» для быстрой локальной проверки визуализации без наличия физических ASIC.
